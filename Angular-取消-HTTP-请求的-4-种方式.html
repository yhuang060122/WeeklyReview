Angular 取消 HTTP 请求的 4 种方式

从最差到最好，根治“旧响应覆盖新数据”的竞态 bug

导语：竞态 bug 的根源不是服务器慢，而是“谁最后到达，谁就赢”。解法只有一条：新请求一发起，旧请求必须死。Angular 22 的 HttpClient 默认走 Fetch API。unsubscribe 会真正 abort 请求，Network 面板里能看到 (canceled)。

4. 手动取消：最差

private sub?: Subscription;

search(q: string) {
  this.sub?.unsubscribe();
  this.sub = this.http.get<Item[]>(...).subscribe(...);
}
ngOnDestroy() { this.sub?.unsubscribe(); }
  • 能跑，但两处 unsubscribe 必须每次都记得。
  • 组件里两个请求 = 两个字段，五个 = 五个。
  • 有人重构时删掉 ngOnDestroy，什么都不报错，bug 悄悄回来。
  • 结论：不是错，是脆弱。
D

3. takeUntilDestroyed()：好一半

this.http.get<User>('/api/me')
  .pipe(takeUntilDestroyed())
  .subscribe(u => this.user = u);
  • 修复：离开页面即取消。无泄漏，无回调。
  • 不修复：搜索竞态。它只在销毁时取消，不在新请求开始时。
  • 同页输入三个字母，三个请求照样赛跑。
  • 用途：一次性加载。别信它处理“用户会触发两次”的场景。
E

2. switchMap：经典解

items = toSignal(
  this.query.pipe(
    debounceTime(300),
    distinctUntilChanged(),
    switchMap(q => this.http.get<Item[]>(`/api/search?q=${q}`))
  ),
  { initialValue: [] }
);

新值一到，switchMap 立刻取消上一个请求。debounceTime(300) 等用户停手。distinctUntilChanged 跳过没变化的文本。toSignal 管订阅和销毁清理。

保存场景禁用 switchMap

点两次 Save，第一次可能已被服务端写入。取消请求 ≠ 撤销写入。保存用 exhaustMap（飞行中忽略新点击）或 concatMap（排队执行）。

F

1. httpResource()：最佳

query = signal('');
q = debounced(() => this.query(), 300);
items = httpResource<Item[]>(() =>
  this.q.value() ? `/api/search?q=${this.q.value()}` : undefined
);
  • 输入变化 → 取消旧请求，发新请求。
  • 组件销毁 → 取消进行中的请求。
  • 返回 undefined → 空搜索框不发请求。
  • isLoading()、error()、value() 全部内置。

Bonus：resource() 和导航取消

用第三方 SDK 或原生 fetch？resource() 在正确时机给你 abortSignal：

items = resource({
  params: () => ({ q: this.query() }),
  loader: ({ params, abortSignal }) =>
    fetch(`/api/search?q=${params.q}`, { signal: abortSignal })
});

仪表盘一次发 10 个请求，用户 1 秒后跳走，它们还在空跑。一个小拦截器解决：

export const cancelOnNav: HttpInterceptorFn = (req, next) => {
  if (req.method !== 'GET') return next(req);
  // 只有读请求被取消
};

第一行是重点：只取消 GET。永远别让导航静默取消付款或保存。

午餐前检查清单

  • 在方法里搜索 .subscribe(——每个都是潜在的竞态。
  • HTTP 调用旁的 mergeMap——几乎都应改成 switchMap。
  • POST/PUT 旁的 switchMap——几乎都应改成 exhaustMap 或 concatMap。
  • DevTools 限速 Slow 4G，快速打字；Network 里看不到 (canceled) 就是 bug。
  • 挑一个界面迁到 httpResource()，感受一下。
