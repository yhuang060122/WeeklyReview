导语：Dataflow 把并发数据处理拆成"块"。块用 linkTo 连接，数据自动流动，背压自动生效，完成信号自动传播。你不用亲手管线程、锁和队列。

A

结论：为什么值得用

核心：把"并发管道"当成"积木 + 传送带"来搭，只写每一块的处理逻辑。

  • 简化开发：高层抽象屏蔽线程细节，代码更干净、更好维护。
  • 高效可扩展：内置背压（backpressure）机制，重负载下不阻塞、不爆内存。
  • 块类型灵活：转换、执行、广播、缓冲、批处理，按需自由组合。
B

什么时候用

  • 并发数据处理：多个块并行执行，吞吐更高。
  • 异步工作流：有依赖、需要同步的异步任务，用 Completion 协调。
  • 复杂数据变换：输入经过多级变换再分发，块式架构最清晰。

块的三种角色

角色 职责 典型块
源块 Source 产出数据，无上游 BufferBlock<int>
目标块 Target 消费数据，不产出 ActionBlock<string>
传播块 Propagator 既消费又产出 TransformBlock<int,string>
D

五种内置块

块 行为 典型用途
TransformBlock<TIn,TOut> 每入一项，出一项 计算、业务逻辑、格式转换
ActionBlock<TIn> 每入一项，执行副作用 I/O、写库、发邮件、打印
BroadcastBlock<T> 同一条数据发给所有下游 一分多发、并行处理同一输入
BufferBlock<T> 缓存并转发，控制流量 临时存储、批处理前排队
BatchBlock<T> 攒够 N 个或超时才放行 成组聚合，减少逐条开销
E

连接 · 过滤 · 完成

  • linkTo(target) 连接块；一个源可连多个目标。
  • 谓词委托过滤消息：linkTo(t, msg => msg.Value > 0)。
  • PropagateCompletion = true：完成信号自动向下游传播。
  • Task.WhenAll(所有块.Completion)：等整条管道收尾。

实战：并行处理 CSV

var importBlock = new TransformBlock<string, IEnumerable<string>>(
    file => File.ReadAllLines(file).Skip(1));

var aggregationBlock = new TransformManyBlock<IEnumerable<string>, KeyValuePair<string,int>>(
    lines => { /* 逐行 Split + AddOrUpdate 聚合 */ });

var printBlock = new ActionBlock<KeyValuePair<string,int>>(r => {
    if (r.Value > 50) Console.WriteLine($"{r.Key}: {r.Value}");
});

var linkOptions = new DataflowLinkOptions { PropagateCompletion = true };
importBlock.LinkTo(aggregationBlock, linkOptions);
aggregationBlock.LinkTo(printBlock, linkOptions);
