httpResource 深入拆解

把 HTTP 请求变成信号：输入一变，旧请求自动取消

sourceAngular 官方文档 angular.dev · httpResource v22 stable

导语：httpResource 是 HttpClient 的响应式包装，把“请求”当成派生信号。输入信号一变，它自动取消旧请求并发新请求。组件销毁时自动清理。加载、错误、数据全是信号。你只声明“数据长什么样”，不用管“什么时候发、什么时候停”。

心智模型

三个自动行为

输入变化 → 取消进行中的旧请求，再发新请求。组件销毁 → 取消进行中的请求。请求函数返回 undefined → 什么都不发。

C

请求函数的三态

请求函数可以返回三种值：

// 1. 字符串 → GET 请求
httpResource(() => `/api/user/${userId()}`);

// 2. 请求对象 → 自定义 method / params / headers 等
httpResource(() => ({
  url: `/api/user/${userId()}`,
  method: 'GET',
  params: { fast: 'yes' },
  headers: { 'X-Special': 'true' },
  reportProgress: true,   // 开启下载进度
  transferCache: true,
}));

// 3. undefined → 不发请求（空搜索框不发）
httpResource(() => this.q.value() ? `/api/search?q=${this.q.value()}` : undefined);
D

HttpResourceRef：返回什么

信号 含义
value() 响应数据，WritableSignal 可写
isLoading() 是否加载中
error() 最近错误
status() idle / loading / reloading / success / error / local
hasValue() 是否有数据
statusCode() / headers() / progress() 状态码 / 响应头 / 下载进度
方法 作用
reload() 主动重发请求
set() / update() 直接写本地值（缓存、乐观更新）
asReadonly() 只读视图
destroy() 手动销毁
别直接读 value()

资源处于 error 状态时读 value() 会抛异常。模板里先用 hasValue() 守卫，再读 value()。

E

取消与生命周期

  • 输入变化 → 取消旧请求，发新请求。旧响应即使到达也被丢弃。
  • 请求重算后没有变化 → 不重复发。
  • 组件销毁 → 取消进行中请求，清理所有信号。
  • reload() → 主动重发；真正发出请求前不进入 reloading。
  • 结果：搜索竞态从根上消失，不需要手动 unsubscribe。

H

坑与建议

  • 别用 httpResource 做 POST / PUT。官方建议 mutation 直接用 HttpClient。
  • error 态读 value() 会 throw，先用 hasValue() 守卫。
  • 请求函数里只读信号，别读组件可变字段。
  • 请求没变化就不会重发，不用手动防抖去重。
  • 搜索框场景：debounced() + undefined 三态组合最省心。
