前端规范全家桶 · Git 提交流水线
提交前四道关卡：触发 → 范围 → 风格/质量 → 规范，坏代码与坏信息进不了仓库
1 git add .
暂存文件
圈定本次改动范围，lint-staged 只盯这里
起点 · 暂存区
→
2 husky
pre-commit 钩子
git commit 前自动触发脚本（.husky 目录）
触发关
→
3 lint-staged
暂存区精准检查
只对本次暂存文件跑脚本，避免全量 lint
范围关
→
4 prettier --write
自动格式化
统一缩进/引号/分号/行宽（.prettierrc.js）
风格关
→
5 eslint --fix
修复 + 质量校验
检测潜在错误与规范问题（.eslintrc.js）
质量关
→
6 commit-msg / Commitizen
提交信息规范化
交互式生成 feat/fix/docs/refactor… 规范信息
规范关
→
✅ 通过
规范的 commit
可读、可追溯、可被 CHANGELOG/发布工具解析
一句话总结：git add 圈定范围 → husky 在 commit 前按关卡放行 → lint-staged 精准拦截 → prettier 管风格、eslint 管质量 → commit-msg/Commitizen 把提交信息写成规范语言。四道关卡共同保证「变更历史可读、可维护、可自动化」。
