JS 模块化与 Webpack · 一图掌握
主线：为什么（痛点）→ 怎么演进（7 时代）→ 用什么规范（4 大规范）→ 怎么落地（Webpack）→ 底层怎么跑（ESM 三阶段）
模块化 = 封装 + 暴露 + 加载
把复杂程序按规范拆成若干文件：内部私有，只通过接口暴露成员，可依赖其他模块。避免命名冲突 / 按需加载 / 高复用 / 高可维护。
没有模块化时的四大痛点
① script 请求过多（Too much HTTP calls）② 依赖模糊（Unclear Dependencies）③ 难以维护 ④ 全局污染、命名冲突
模块化好处
减少命名空间污染 · 更好的分离与按需加载 · 更高复用性 · 高可维护性

② 四大规范对比（AMD vs CMD 差异 = 依赖前置/就近 × 提前/延迟执行）
规范环境 / 实现定义模块加载模块依赖 / 执行时机
CommonJS服务器 / Node.jsmodule.exports·exports.xxxrequire('id')依赖就近 · 同步运行时
AMD浏览器 / RequireJSdefine(id?, deps, factory)require([mod], cb)依赖前置 · 提前执行
CMD浏览器 / SeaJSdefine(function(require, exports, module){})require / require.async依赖就近 · 延迟执行
ES6通用 / 语言层面export·export defaultimport ... from静态分析 · 编译期
③ ES6 语法三件套 · ④ ESM 内部三阶段 · ⑤ Webpack 落地
ES6 语法（导出 / 导入）
默认：export default {...} ⇄ import m1 from './m1.js'（每模块仅一次）
按需：export let s1=... ⇄ import { s1, s2 as ss2 } from '...'
直接执行：import './m2.js'（不取成员只跑代码）
ESM 三阶段（vs CommonJS）
构建：解析→下载→模块记录（Module Map 缓存）
实例化：开内存、导出/导入指向同一地址（实时绑定）
评估：执行顶层代码填值（深度优先后序，副作用只跑一次）
CJS：一次同步完成 · 导出值复制；ESM：分阶段异步 · 实时绑定 · 支持循环依赖
Webpack 工作流
入口 src/index.js → 出口 dist/main.js（entry/output/mode）
loader 管线：style→css→postcss(autoprefixer)→sass · url-loader(limit 转 base64) · babel-loader(exclude node_modules)
webpack-dev-server 自动打包（localhost:8080，虚拟产物）+ html-webpack-plugin 预览 → 发布压缩混淆
