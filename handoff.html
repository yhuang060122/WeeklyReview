01 这是什么

WeeklyReview 是一个静态站点：仓库根目录的每个 *.html 都是一份独立文档（周复盘看板或学习笔记）。推送 main 分支后，GitHub Actions 自动打包部署到 GitHub Pages，目录页 index.html 通过 JavaScript 读取构建时生成的 manifest.json 动态渲染导航，因此新增文档无需手工改目录页。

  • 站点地址：https://yhuang060122.github.io/WeeklyReview/
  • 仓库地址：git@github.com:yhuang060122/WeeklyReview.git
  • 部署方式：push 触发，或在 Actions 页手动触发（workflow_dispatch）

02 文件结构

文件 / 目录作用需要维护？
index.html目录导航页（JS 动态渲染）否（自动）
*.html（根目录）各周复盘与学习笔记正文是（新增/改名时）
favicon.png / favicon.ico站点图标（秋日枫叶，随站部署）想换图标时替换这两个文件即可
manifest.json目录元数据，CI 构建时生成否（自动，勿手改）
scripts/generate_manifest.py扫描 HTML、提取标题、分类排序仅改分类规则时
.github/workflows/deploy.yml部署工作流否
.nojekyll跳过 Jekyll，按静态文件发布否

04 日常操作

① 新增一篇文档（最常用）

  1. 把 HTML 复制到仓库根目录，按上方约定命名。
  2. 提交并推送：
    git add -A
git commit -m "add: <文档名>"
git push origin main
  3. 约 1 分钟后，目录页自动出现新卡片（打开 manifest.json 可确认）。

② 重命名 / 删除

git mv "旧文件名.html" "新文件名.html"   # 重命名（保留历史）
git rm "文件名.html"                     # 删除
git push origin main

改名后旧链接会 404，如已在别处引用需同步更新。

③ 调整分类 / 标签

编辑 scripts/generate_manifest.py 的 classify() 函数，推送后自动生效。当前标签规则：

文件名含关键词标签

llm / 大模型 / geminiAI

以上都不含笔记

05 部署机制

推送 main 后工作流 deploy.yml 依次执行：

  1. Checkout 代码 → Configure Pages
  2. 把根目录 *.html、.nojekyll 与 favicon.* 复制进 public/
  3. 运行 python3 scripts/generate_manifest.py public 生成 manifest.json
  4. 上传产物并部署到 GitHub Pages

部署状态查看：仓库 Actions 页，绿色 = 成功；站点地址即上方的 GitHub Pages URL。

06 常见问题排查

现象原因 / 处理
目录页显示「目录加载失败」用 file:// 直接双击打开时浏览器会拦截 fetch。请通过 GitHub Pages 地址访问，或本地起服务：python -m http.server
推送后目录没更新先看 Actions 是否成功；若成功则是 CDN 缓存，强制刷新（Ctrl/Cmd + F5）
部署在 Configure Pages 步骤失败仓库 Settings → Pages → Source 选择 GitHub Actions（只需一次）
卡片分类不对文件名未按命名约定；或需在 classify() 中加关键词规则
标题显示为文件名HTML 里没有 <title> 标签，脚本会退回用文件名
